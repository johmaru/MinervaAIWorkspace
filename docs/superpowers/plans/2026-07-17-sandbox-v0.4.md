# Sandbox v0.4 Implementation Plan (Tier 1 / code_run)

> **For agentic workers:** Implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.  
> **Spec:** [2026-07-15-sandbox-architecture-design.md](../specs/2026-07-15-sandbox-architecture-design.md) (D1–D10)  
> **Status:** Ready to implement  
> **Created:** 2026-07-17

**Goal:** Ship experimental Tier 1 sandbox code execution: Docker-only isolation, thin `sandbox_run` tool, request-scoped containers, admission control, run staging, structured errors. No Tier 2/3 pipelines yet.

**Architecture (v0.4):**

```
LLM tool call sandbox_run
  → src/lib/sandbox (policy + admission + staging + lifecycle)
  → docker CLI (create/run/rm) with prebuilt image
  → sanitized JSON result back to tool loop
```

- Lifecycle lives **in-process** behind `SandboxLifecycle` (D2).
- Chat exposes **one tool** `sandbox_run` only when Docker is available (D1, D3).
- **No** process-isolation fallback. **No** async jobs (D6). **No** warm pool.

**Tech Stack:** TypeScript, Next.js App Router, Vitest 4, Docker CLI (`docker` binary), `node:child_process` / `node:fs` / `node:os`. Prefer **no new npm deps** (no dockerode) unless CLI proves insufficient.

### Environment variables (implement these names)

| Variable | Default | Meaning |
|----------|---------|---------|
| `SANDBOX_ENABLED` | `auto` | `auto` = enable if Docker ok; `true` = require Docker (fail tool if not); `false` = force off |
| `SANDBOX_IMAGE` | `umanschat-sandbox-python:v0.4` | Prebuilt image tag |
| `SANDBOX_MIN_FREE_MEM_PERCENT` | `15` | Reject new runs when free/available mem % below this |
| `SANDBOX_MAX_CONCURRENT` | `1` | Max simultaneous sandbox containers |
| `SANDBOX_DEFAULT_TIMEOUT_SEC` | `30` | code_run timeout |
| `SANDBOX_STDOUT_MAX_BYTES` | `4096` | stdout/stderr cap after sanitize |

### Nested Docker note

When the **app itself** runs in Compose, spawning sibling containers needs the host Docker socket mounted into the app container (e.g. `/var/run/docker.sock`) **or** users run the app on the host with Docker Desktop. Document in install skill; optional compose snippet in Task 9.

export type SandboxPresetName = "code_run" | "file_inspect" | "malware_analysis";

      stderr?: string;
      stdoutTruncated?: boolean;

      error: { code: SandboxErrorCode; message: string };

  file_inspect: { securityTier: 2, timeoutSec: 60, implemented: false },
  malware_analysis: { securityTier: 3, timeoutSec: 60, implemented: false },
};

export function sandboxFail(code: SandboxErrorCode, message: string): SandboxRunResult {
  return { ok: false, error: { code, message } };
}

### Task 3: Policy gate (D7)

**Files:**
- Create: `src/lib/sandbox/policy.ts`
- Create: `src/lib/sandbox/policy.test.ts`

**API:**

```ts
export type PolicyOk = {
  ok: true;
  preset: "code_run"; // only implemented
  tier: 1;
  language: "python" | "javascript" | "typescript" | "bash";
  code: string; // required for v0.4 success path
};

export type PolicyErr = { ok: false; result: SandboxRunResult };

export function evaluateSandboxPolicy(args: unknown): PolicyOk | PolicyErr;
```

**Rules (v0.4):**
1. Parse/validate shape → else `invalid_args`
2. Unknown preset → `preset_unknown`
3. `file_inspect` / `malware_analysis` → `tier_forbidden` (not implemented)
4. `inputRef` present → **reject** with `tier_forbidden` or `unsupported_input`  
   (attached scripts/binaries need Tier ≥2; v0.4 has no implement path — **no silent Tier 1**)
5. `code` required for `code_run`; non-empty string; optional max length (e.g. 100_000 chars) → `invalid_args`
6. `language` default `python`; reject unsupported → `invalid_args`
7. Success only: preset `code_run`, inline code, tier 1

**Magic-byte helpers (stub for later):**  
`classifyInputRef` can remain unimplemented; any `inputRef` fails closed.

- [ ] **Step 1:** Table-driven tests for each rule above.
- [ ] **Step 2:** Implement `evaluateSandboxPolicy`.
- [ ] **Step 3:** Tests pass.

**Interfaces:**

```ts
// lifecycle.ts
export type SandboxExecRequest = {
  runId: string;
  image: string;
  language: PolicyOk["language"];
  hostStagingDir: string; // bind-mount source
  timeoutSec: number;
  memLimitMb?: number; // e.g. 256
};

export type SandboxExecSuccess = {
  exitCode: number;
  stdout: string;
  stderr: string;
  timedOut: boolean;
};

export interface SandboxLifecycle {
  exec(req: SandboxExecRequest): Promise<SandboxExecSuccess>;
}

// dockerDetect.ts
export function isSandboxForcedOff(): boolean; // SANDBOX_ENABLED=false
export async function isDockerAvailable(): Promise<boolean>; // docker info
export async function isSandboxImagePresent(image: string): Promise<boolean>;
export async function shouldExposeSandboxTool(): Promise<boolean>;
```

**Docker run shape (code_run):**

```bash
docker run --rm \
  --network none \
  --memory <memLimitMb>m \
  --pids-limit 64 \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=64m \
  -v <hostStagingDir>:/work:ro \
  -w /work \
  <image> \
  <language-specific command>
```

Language commands (image provides runtimes):
- python: `python main.py`
- javascript: `node main.js`
- typescript: `node main.js` only if we transpile in orchestrator **or** limit v0.4 languages to `python` + `javascript` first — **prefer v0.4: `python` and `javascript` only**; map `typescript` → `invalid_args` or transpile later
- bash: `bash main.sh` only if image has bash — **optional; can defer bash**

**Plan default for v0.4 languages:** `python` | `javascript` only (update policy Task 3 if needed). Document in types.

**Timeout:** kill container (docker run with context deadline or `docker kill`); surface `timedOut: true` and orchestrator maps to `timeout` error code **or** ok with exit and flag — prefer **`ok: false, code: timeout`** when timed out for clearer tool semantics.

**Injectable `runCommand(argv: string[], opts)`** for tests.

### Task 8: Orchestrator `runSandbox`

**Files:**
- Create: `src/lib/sandbox/index.ts`
- Create: `src/lib/sandbox/index.test.ts`
- Create: `src/lib/sandbox/toolDef.ts` (OpenAI tool JSON for `sandbox_run`)

**Flow:**

```
runSandbox(args: unknown): Promise<SandboxRunResult>
  1. if forced off or !docker → docker_unavailable (or should not be called)
  2. policy = evaluateSandboxPolicy(args); if !ok return result
  3. admission check; if fail return
  4. image present? else image_missing
  5. withSandboxSlot:
       create staging, write code file
       try lifecycle.exec(...)
       sanitize stdout/stderr
       map timeout / failure
       finally remove staging
  6. return ok:true with tier 1, exitCode, sanitized streams
```

Also export:
- `getSandboxToolDefinition(): ChatCompletionTool`
- `async function getSandboxToolsForRequest(): Promise<ChatCompletionTool[]>` → `[]` or `[def]` based on `shouldExposeSandboxTool()`

Mark tool results for the model: prefix message content with a short untrusted marker, e.g.  
`[sandbox untrusted output]\n` + `JSON.stringify(result)` so the chat model treats data as untrusted (Tier 1 sanitize).

- [ ] **Step 2:** Implement `runSandbox` + tool def.

## Risk notes for implementers

1. **Docker Desktop memory** vs `os.freemem()`: admission may be approximate; err on the side of rejecting (`insufficient_host_memory`) rather than OOM host.
2. **Path mounts on Windows:** bind mount paths for Docker Desktop need path conversion sometimes (`C:\` → `/c/...` or Docker accepts Windows paths depending on version). Test on Windows host; encapsulate in `dockerLifecycle` helper `toDockerVolumePath(hostPath: string)`.
3. **App-in-Docker without sock:** feature correctly off; do not half-enable.
4. **Tool output size:** keep JSON small; truncation flags set when hit.
5. **Security:** never `docker run` with user-controlled image name or network mode; image from env only; args only from policy-approved fields.
